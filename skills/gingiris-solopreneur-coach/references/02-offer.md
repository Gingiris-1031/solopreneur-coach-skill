# Package expertise / 经验服务化

## English

Use when a capability needs to become a understandable, deliverable offer. Skip an inventory if the user already has a clear offer.

Review one to three relevant projects: original task, personal actions, organizational support, observable results, and permission to share. Select one independently deliverable unit. No shareable case? Use an anonymized structure or clearly labeled demonstration, never fabricated testimonials.

Draft:
```text
I help [specific person in a situation] achieve [observable deliverable]
using [method], so they can [next use].
Client inputs and responsibilities:
Deliverables, format, quantity:
Start conditions and timeframe:
Included communication, revisions, and support:
Exclusions and dependencies:
Acceptance method:
Capability evidence:
Still testing: demand / ability / payment / repeatability
```

Have a relevant person explain what they think they would receive. Fix misunderstandings; understanding is not purchase validation. Create a sample only if capability evidence is missing. Define its scope, time cap, cooperation, end date, and use rights before work. Free or discounted work is optional and never means unlimited revisions or permission to publish.

Illustration, not a client result: audit one landing page and deliver annotated issues with priorities for the client's designer. Exclude implementation and guaranteed conversion uplift. Track baseline, personal work, client implementation, time, and observed results separately.

A short case record needs: problem, initial state, personal work, others/dependencies, result/evidence, limits/sharing rights. If independent delivery is not feasible, narrow scope or build the missing capability. If the offer is understood but no urgent use appears, return to demand research.

An initial 15-minute action: rewrite one past task as a bounded deliverable. A full draft may take longer; estimate after seeing the material.

## 中文

适用于把能力变成客户能理解、自己能交付的服务。已有清晰服务就跳过盘点。

查看一到三个相关项目：原任务、本人动作、组织支持、可观察结果、公开权限。选一个可独立承担的工作单元。没有可分享案例时使用脱敏结构或明确标注的演示，不伪造背书。

起草：
```text
我帮助〔具体情境中的某类人〕，通过〔方法〕完成〔可观察成果〕，
供其用于〔下一步用途〕。
客户输入与责任：
交付物、格式、数量：
启动条件与周期：
包含的沟通、修改与支持：
排除项和依赖：
验收方法：
能力证据：
仍需验证：需求 / 能力 / 付费 / 重复性
```

请接近目标客户的人复述会得到什么，修正误解；理解不等于购买验证。只有缺少能力证据时才做样例，提前明确范围、时间上限、配合、结束日期和使用权。免费或折扣可选，不代表无限修改或授权公开。

教学示例，非客户结果：检查一个官网页面，交付带标注的问题和优先级供客户设计师使用，排除开发与保证转化提升。分开记录基线、本人工作、客户实施、工时和观察结果。

案例卡保留问题、初始状态、本人工作、其他人和依赖、结果与证据、限制与公开权。无法独立交付则缩范围或补能力；对方理解但没有急迫用途则返回需求研究。

15分钟起手动作：把一件过去做过的事改写成有边界的交付物。完整草案可能更久，看材料后再估。
